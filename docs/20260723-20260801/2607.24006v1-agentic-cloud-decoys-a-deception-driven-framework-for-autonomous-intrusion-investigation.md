## 摘要
云遥测数据以如此规模到来，反而使入侵理解更加困难而非更容易。攻击者通过合法身份、联合会话令牌和与日常管理难以区分的云原生 API 进行操作，而分析师在事件发生后花费精力重建日志中本已包含的上下文。我们提出了 Cloud Decoy AI Agent 框架，该框架将高保真云诱饵与自主语言模型代理相结合，压缩了从可疑活动到分析师就绪报告的路径。将诱饵连接到代理并非简单的接线工作。调查的单位是会话而非事件，且会话密钥被联合凭证引入的身份分层所掩盖。代理的证据范围必须有限，因为若允许代理自由查询完整的控制平面历史，它就会继承欺骗本应消除的成本和误报特性。而且，云遥测部分由对手编写，因为对象键和用户代理字符串是攻击者选择的值，提供商会逐字记录，这使得任何“日志到提示”的路径都成为间接提示注入通道，而诱饵扩大而非缩小了这一通道。我们通过以下方式解决前两个问题：采用基于仅从提供者派生字段提取的枢轴元组的会话聚合运算符；以及采用动态提示生成——一种两阶段提示组装方法，通过仅携带代理观察到的字段来强制实现基础不变性。我们将第三个问题识别为这类系统中未解决的安全暴露，指出了其所需的缓解措施，并说明我们的原型未实现该措施。在十个受控 AWS S3 场景中，九个被完全重建，没有任何报告包含无法追溯到已观察工件的主张，延迟为四到五分钟。我们还说明了本次评估未能确立的内容，并提出了能够对此做出定论的比较方法。

## Abstract
Cloud telemetry arrives at a scale that, paradoxically, makes intrusion understanding harder rather than easier. Attackers operate through legitimate identity, federated session tokens, and cloud native APIs indistinguishable from routine administration, and analysts spend an incident reconstructing context the logs already contain. We present Cloud Decoy AI Agent, a framework pairing a high fidelity cloud decoy with an autonomous language model agent that compresses the path from suspicious activity to an analyst ready report. Connecting a decoy to an agent is not a wiring exercise. The unit of investigation is the session rather than the event, and the session key is obscured by the identity layering federated credentials introduce. The agent's evidence horizon must be bounded, since an agent free to query full control plane history inherits the cost and false positive profile deception was meant to remove. And cloud telemetry is partly adversary authored, since object keys and user agent strings are attacker chosen values providers record verbatim, which makes any log to prompt path an indirect prompt injection channel that a decoy widens rather than narrows. We address the first two with a session aggregation operator over a pivot tuple drawn only from provider derived fields, and with dynamic prompt generation, a two stage prompt assembly enforcing a grounding invariant by carrying only fields the agent observed. We identify the third as an unaddressed exposure in this class of system, specify the mitigation it requires, and note our prototype does not implement it. Across ten controlled AWS S3 scenarios, nine were reconstructed completely, no report contained an assertion untraceable to an observed artifact, and latency was four to five minutes. We also state what this evaluation does not establish and name the comparisons that would settle it.

### 1. 核心问题与研究动机

云环境中的遥测数据量极大，但并未使入侵调查变得更容易，反而因“可见性悖论”而更加困难：CloudTrail 等控制面日志记录了几乎所有 API 调用，但攻击者通过合法凭证、联合会话令牌和云原生 API 进行活动，其表面特征与常规管理操作难以区分。一个真实的攻击行为（如 ListObjects、GetObject）也是开发者或自动化管线的日常操作。因此，分析师从初始告警到获得调查信心的过程通常耗时数小时甚至数天，瓶颈在于**重建（reconstruction）延迟**而非检测覆盖率。

现有欺骗/蜜罐技术能提供高信噪比的告警信号，但在“诱饵被触碰之后”缺乏自动化处理路径，仍需人工分析。同时，大语言模型在日志分析中的应用缺乏证据约束和注入防护。本文旨在将**高保真云诱饵**与**自主 LLM 代理**相结合，压缩从可疑活动到分析师就绪报告的时间路径。

### 2. 方法论与关键技术

**总体框架：Cloud Decoy AI Agent**

- 架构为六层流水线：诱饵资源（S3 桶）→ CloudTrail/EventBridge 事件路由 → Lambda 摄取与规范化 → DynamoDB 会话存储 → SQS 触发代理 → 代理工具调用与动态报告生成。

**核心设计：**

- **事件形式化投影**：每个 CloudTrail 事件投影为十元组 e = ⟨t, ι, κ, ρ, β, a, o, ε, u⟩，分为**提供者派生字段** T = {t, ι, κ, ρ, β, a, ε} 和**客户端提供字段** A = {o, u}（对象键和用户代理，潜在对抗输入）。
- **枢轴元组（Pivot Tuple）**：π(e) = ⟨ι, κ, ρ, β⟩，即源地址、访问密钥、主体、目标桶，全部来自提供者派生字段，使对手无法通过写入内容影响自身的活动分组。
- **会话（Session）**：具有相同枢轴值的最大事件子集，相邻事件时间间隔不超过空闲阈值 τ（原型取 15 分钟）。
- **证据界定性不变式（Invariant 1）**：报告中每个事实断言必须由证据包 P 中的某字段推出，且不得对证据包中缺失的字段进行断言。该不变式通过**动态提示生成（Dynamic Prompt Generation）** 结构化地执行——提示仅携带代理实际观察到的字段，缺失字段直接省略而非用占位符填充，从机制上消除模板填充引发的幻觉。
- **两阶段提示组装**：静态系统提示定义角色与约束（只使用给定证据、保持时序、区分成功与失败、不虚构 IoC）；动态用户提示按会话从证据包生成。
- **攻击图构建**：带类型的节点（Principal、Credential、Address、Resource、Object）和边（authenticated as、assumed、used、acted on、touched），满足闭世界条件——没有节点或边可在无观察字段支持下存在，结构上支撑 Invariant 1。
- **MCP 工具接口**：通过 Model Context Protocol 暴露四个工具（cloudtrail_history、identity_context、s3_security_context、attack_graph），每个工具运行在最小权限 IAM 角色下。
- **威胁模型**：假设日志是部分对抗作者化的信道——对象键、请求参数和用户代理字符串是对手选择的值，提供者逐字记录，任何日志到提示的管线都是间接提示注入通道，诱饵设计**扩大**而非缩小了此暴露面。论文明确该原型**未实现**完整缓解（字段截断转义、哈希化读取、数据/指令分隔区、输出转义）。
