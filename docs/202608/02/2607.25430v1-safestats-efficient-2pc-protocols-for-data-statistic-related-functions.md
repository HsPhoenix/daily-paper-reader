## 摘要
对敏感数据集（如医疗记录和金融交易）进行统计分析对决策至关重要，但也引发了重大的隐私担忧。尽管现有的安全两方计算（2PC）在设计通用安全原语（例如加法与乘法）或机器学习相关函数方面做出了大量努力，但很少关注统计函数。本文提出了 SafeStats，一个专为两方安全统计分析定制的安全工具包。具体而言，为开发 SafeStats，我们首先参考微软 Excel 的统计函数库，总结出大多数统计操作可通过三个核心函数实现：1）频数计数，2）排序，以及 3）非线性数学函数。然后，针对每个核心统计函数，SafeStats 均提供了高效的 2PC 实现。对于安全频数计数，SafeStats 采用基于安全移位（shift）的策略，避免调用开销高昂的两方安全相等性测试协议。对于安全排序，SafeStats 引入安全的段指示符（segment-indicator）协议以实现基于计数的安全排序，从而在特定统计场景下无需安全比较即可快速完成元素排序。对于非线性数学函数，我们通过引入一种基于二分法的范围缩减协议，增强了当前“先缩减后近似（reduce-then-approximate）”的范式。最后，我们实现了 SafeStats，并在 14 个常见统计分析案例上进行了测试。以卡方检验为例，与直接使用现有通用 2PC 库实现相比，SafeStats 实现了 1.5 倍的运行时间加速和 4.2 倍的通信量减少。

## Abstract
Statistical analysis on sensitive datasets like medical records and financial transactions is essential for decision-making, but raises significant privacy concerns. While existing secure Two-Party Computation (2PC) makes extensive efforts in designing the common secure primitives (e.g., addition and multiplication) or machine learning-related functions, few pay attention to the statistical functions. In this paper, we propose SafeStats, a secure toolkit tailored for 2PC secure statistical analysis. Specifically, to develop SafeStats, we first refer to Microsoft Excel's statistical library and summarize that most statistical operations can be achieved with three core functions:1) frequency counting, 2) sorting, and 3) non-linear math functions. Then, for each core statistical function, SafeStats presents an efficient 2PC implementation. For secure frequency counting, SafeStats adopts a secure shift-based strategy to avoid invoking expensive 2PC equality test protocols. For secure sort, SafeStats involves a secure segment-indicator protocol to achieve secure counting-based sort, which enables fast element sorting over specific statistical scenarios without the need for secure comparison. For non-linear math functions, we enhance the current reduce-then-approximate paradigm by introducing a bisection-based range reduction protocol. Finally, we implement SafeStats and test it on 14 common statistical analysis cases. As an example, for the chi-square test, SafeStats achieves a 1.5 $\times$ runtime speedup and a 4.2 $\times$ reduction in communication compared to directly using the current general-purpose 2PC library to realize it.

## 2. 论文提出的方法论

### 核心观察
参考微软 Excel 统计函数库，将统计操作归类为三类核心构建模块：

| 类别 | 代表操作 | 用途 |
|------|----------|------|
| 频数计数 | Mode、CHISQ.Test | 计数相关统计 |
| 排序 | Median、Rank、Min/Max、Percentile | 顺序相关统计 |
| 非线性数学函数 | Std、Skew、Kurt、回归分析 | 代数型统计函数 |

### 关键技术一：安全频数计数（Secure Frequency Counting）
- **核心思想**：此前方法需要对每个输入 x 与每个取值 v ∈ [0, m−1] 逐一执行相等测试，复杂度为 O(mℓ) 次 OT 调用。SafeStats 观察到：对输入 x 的相等测试结果可表示为长度为 m 的单位布尔向量 ⃗e_x，而 ⃗e_x 可通过单位向量 ⃗e_0 按偏移量 x 循环移位得到。这样只需 O(log m) 次 OT 即可完成一次"隐 oblivious shift"，替代 O(mℓ) 的相等测试。
- **协议流程**：利用 FRVOSE 功能实现安全的向量循环移位，输入共享 ⟨x⟩，双方分别持有偏移量份额，通过两次循环移位组合得到单位向量 ⃗e_x，再通过 FB2A 转换并累加得到频率向量。
- **CRT 优化（定制模式）**：当众数频率超过 n/2 时，利用中国剩余定理将特征域分解为若干互素的子域（N = ∏tᵢ ≥ m），在更短的子域向量上分别求众数，再通过 CRT 重构全局众数，以降低通信开销。

### 关键技术二：安全排序（Secure Counting Sort）
- **核心思想**：针对大样本、小特征域（m ≤ log²n）的统计场景，用计数排序替代比较排序，避免性能瓶颈——安全比较。
- **段指示符协议（Segment-Indicator Protocol）**：给定私有输入 a、b，输出在区间 [a, b] 上为 1、其余为 0 的秘密共享指示向量 ⃗1_{a:b}。构造方式：通过 ⃗1_{1:b} − ⃗1_{1:a−1} 得到，而 ⃗1_{1:b} 可由单位向量 ⃗e_b 的后缀和求得。
- **批量插入**：相比此前逐元素顺序插入（电路深度 O(n)），SafeStats 通过一次元素级乘法将所有具有相同值的元素批量插入输出向量，电路深度降为 O(1)。
- **Percentile 优化**：将百分位数求解重构为"区间测试"问题——判断第 k 小值落在哪个频数前缀和区间内，绕过完整排序，仅需 m−1 次 F_Mill、m−2 次 F_AND 和 m 次 F_B2A。

### 关键技术三：安全非线性数学函数（Secure Non-linear Math Functions）
- **二分法 MSNZB 协议**：现有 SIRNN 方案通过线性策略逐位扫描 d 个数字块定位最高非零位（MSNZ），需要 O(d) 轮通信。SafeStats 观察到 MSNZ 数字块总位于非零半区，据此提出递归二分定位协议，将通信轮数降至 O(log d)。
- **区间压缩协议（Interval Compression）**：理论分析（Lemma 1、Lemma 2）表明，将输入归一化区间 [2^k, 2^(k+1)) 压缩至 [2^k, 1.5 × 2^k) 可将多项式逼近误差从 1/(2^(2n+1)2^k) 降至 1/(2^(3n+2)2^k)，从而在相同精度下使用更低阶多项式，或在相同阶数下获得更高精度；对迭代法（如牛顿迭代）也可减半 LUT 大小。

## 6. 论文主要结论与发现

1. **频数计数**：SafeStats 基于安全移位的方案相比基于相等测试的方案，实现 4.0-7.9× 的运行时间提升和 3.1-8.6× 的通信量减少；相比位分解方案也有 1.1-3.0× 的速度提升。
2. **安全排序**：在特征域 m ≤ log²n 的统计场景下，SafeStats 相比 QuickSort 基线实现 3.4-20.5×（LAN）乃至约 90×（WAN）的运行时间加速，通信量减少 1.3-7.6×；相比 RadixSort 在小特征域下有显著优势，但在 m = 1024 时性能与之相当（略慢 1.1×）。
3. **非线性函数**：二分法 MSNZB 协议较线性策略降低通信 1.47×，LAN 下加速 2.48×，WAN 下加速 1.61×；端到端函数（1/x、1/√x、ln x）通信减少约 1.15-1.16×。
4. **端到端案例**：14 个统计函数全部获得优化。卡方检验取得 1.5× 运行加速和 4.2× 通信减少；排序类函数收益最大（Rank 在 WAN 下达到 205.4× 加速），而乘法密集型函数（如 Std）收益较小。
5. **局限性说明**：基于计数排序的协议仅适用于特征域较小的统计场景（m < log²n），当 m 增大至与 n 同量级时，其优势消退。

## 7. 优点

- **问题定位精准**：指出现有 2PC 研究空缺——统计函数缺乏专门优化，而非简单复用通用原语；通过 Excel 统计函数库的归纳分析，把看似繁杂的统计操作化约为三个核心函数，为协议设计提供了清晰且合理的目标。
- **理论创新扎实**：
  - 频数计数中"相等测试 → 向量移位"的视角转换极具巧思，用 O(log m) OT 替代 O(mℓ) OT；
  - 段指示符协议实现了 O(1) 电路深度的批量计数排序，大幅降低了此类排序的通信轮数；
  - 二分法 MSNZB 将通信轮数从 O(d) 降为 O(log d)；
  - 区间压缩协议不仅给出了具体的归一化方法（Lemma 2），还给出了逼近误差的理论分界（Lemma 1），提供了协议设计之外的正交优化方向。
- **工程完成度高**：实现了完整工具包并在 14 个统计案例上验证，提供公开代码链接；实验同时报告了运行时间、通信量和数值精度，度量维度全面。
- **安全性论证规范**：采用 UC 框架，对核心协议给出了完整的模拟器安全性证明，而非简单的"直观安全"说明。

## 8. 不足与局限

- **适用范围受限**：
  - 计数排序协议仅在特征域 m 较小（m < log²n）时具有优势，当 m 与 n 同量级时性能回落甚至不如 RadixSort；
  - CRT 优化模式的前提是众数频率超过 n/2，对一般情况不适用。
- **实验覆盖不足**：
  - 只在单机模拟网络上运行，缺乏多机真实网络部署验证；
  - 仅使用一个真实数据集（学生成绩），未覆盖医疗、金融等其他敏感数据场景；
  - 对 14 个案例中的部分函数，论文承认此前没有专门 2PC 实现可对比，基线的"公平性"有待更多第三方验证。
- **缺少深入消融**：区间压缩对具体函数（1/x 等）的贡献度未单独拆解分析；CRT 优化的收益边界（众数频率变化时的性能曲线）未系统评估。
- **精度与安全细节处理**：虽然报告了 ULP error，但对定点数位宽选择对统计结果的实际影响（如卡方检验的统计显著性）未讨论。
