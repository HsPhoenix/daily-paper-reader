## 摘要
安全性和隐私性是联邦学习（FL）的基本要求，尤其是在医疗和基因组学等需要分析敏感信息的领域。我们的FL框架旨在应对这些挑战，同时提出一种模块化、灵活且基于微服务的架构。更具体地，它集成了高效的gRPC通信层和有限状态机，以确保组件同步的鲁棒性和威胁检测，同时依赖于使用CKKS同态加密系统的阈值变体的容错安全聚合协议。这允许编排服务器进行盲模型聚合，要求至少t-out-of-N个活动客户端参与解密，同时通过密码学和网络协议最小化通信开销。我们通过噪声泛洪确保IND-CPA-D安全性，并通过每轮更新集体密钥材料来缓解针对同步解密器的最新密钥恢复攻击。我们通过多种用例展示了该框架的有效性，从标准图像识别（EMNIST）到复杂的基因组分类（包括TCGA上的乳腺癌亚型分型），并评估了不同阈值和模型规模下的系统性能。

## Abstract
Security and privacy are primordial requirements for Federated Learning (FL), especially in fields such as healthcare and genomics where sensitive information has to be analyzed. Our FL framework is designed to address these challenges while proposing a modular, flexible and micro-service architecture. More precisely, it integrates an efficient gRPC communication layer and a Finite State Machine to ensure robust component synchronization and threat detection, while relying on a fault-tolerant secure aggregation protocol using a Threshold variant of the CKKS homomorphic cryptosystem. This allows blind model aggregation by an orchestration server, requiring a minimum of $t$-out-of-$N$ active clients for decryption while minimizing communication overhead thanks to both cryptographic and network protocols. We ensure IND-CPA-D security through noise flooding and mitigate the recent key-recovery attack on synchronized decryptors by renewing the collective key material at every round. We demonstrate the framework's effectiveness through diverse use cases, ranging from standard image recognition (EMNIST) to complex genomic classification including breast cancer subtyping on TCGA, evaluating system performance across different threshold values and model scales.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：联邦学习（Federated Learning, FL）允许多方在不共享原始数据的情况下协作训练全局模型，但传统 FL 存在严重的安全与隐私缺陷，如模型反演攻击、成员推断攻击、属性推断攻击等。
- **核心问题**：在医疗和基因组学等高度敏感的场景中，FL 需要同时满足安全隐私、模型多样性、部署异构性和鲁棒监控四大需求，而现有 FL 框架（如 Flower、FATE、PySyft）只能部分满足：
  - 多数框架不支持**门限同态加密（ThHE）**，仅使用单密钥同态加密，依赖可信聚合器，存在单点故障；
  - 架构上存在模块化不足（FATE 的单一 monolithic 设计）或语言绑定问题（PySyft 深度绑定 Python，难以与 C++/Rust 等高性能密码学语言集成）；
  - 缺乏对客户端中途掉线的容错机制，无法在部分客户端不可用时完成协作解密。
- **整体含义**：作者提出 **MOSAIC-FL**（Modular and Secure Federated Learning via Microservice Orchestration），一个基于微服务的模块化隐私保护 FL 框架，并将其应用于基因组学中的乳腺癌亚型分类，是**率先将多密钥/门限 FHE 与 FL 结合用于组学数据**的工作之一。

## 2. 论文提出的方法论

### 2.1 总体架构：微服务 + 严格职责分离
- 每个联邦节点由一个容器集群构成，包含三个核心实体：
  - **Orchestrator（编排器）**：节点的"中央大脑"和唯一对外网关，负责与聚合服务器及其他客户的通信、管理节点生命周期、实现**有限状态机（FSM）** 以同步联邦轮次和密码协议、检测故障与恶意行为；
  - **ML Engine（机器学习引擎）**：纯被动服务，只负责张量操作和模型训练，不接触网络与密码逻辑；
  - **Crypto Provider（密码提供方）**：处理密钥生成、同态加密等敏感密码操作，同样以被动"拉取"模式运行，容器设计可轻松替换（当前实现为 ThHE-CKKS）。
- 内部 API 采用 gRPC + Protocol Buffers，相比 REST/JSON 降低序列化开销、强制类型安全、原生支持大模型权重和密文的二进制负载。
- 组件间禁止直接通信（图中红色标记），以最小化内部攻击面。

### 2.2 密码学基础：门限 CKKS 同态加密（ThHE）
- 采用 Mouchet et al. (2023) 的 RLWE 门限同态加密方案，实例化为多密钥版 CKKS，支持 **t-out-of-N** 门限结构。
- 核心算法流程：
  1. **Setup (1^λ, N, t)**：输出公共参数；
  2. **DistKeyGen**：各客户端联合生成集体公钥 pk，集体私钥 s 被加性共享为各客户端的私密份额 s_i；
  3. **Enc (pk, m)**：客户端用集体公钥加密本地模型更新；
  4. **Eval**：服务器在密文域上同态计算联邦平均聚合 W = Σ (n_k/n)·Enc(w_k)（n_k 为各客户端本地样本数）；
  5. **ShareReshare**：基于 Shamir 秘密共享（在密文环上）将私钥份额重新分配为 t-out-of-N 门限结构；
  6. **PartDec**：每个客户端对聚合密文计算部分解密份额 d_j = c₁·s̃_j + e′_j（含新鲜噪声，即噪声泛洪）；
  7. **CombDec**：任意收集到 ≥ t 个份额的节点，通过拉格朗日插值恢复明文全局模型 m = c₀ + Σ λ_j·d_j。
- **安全性**：
  - 安全模型假设聚合服务器为"诚实但好奇"（honest-but-curious）半自适应敌手，且每轮至少 t 个客户端为诚实节点、客户端之间不共谋；
  - 通过噪声泛洪（noise flooding）实现 **IND-CPA-D** 安全；
  - 针对同步 ThHE 方案上的密钥恢复攻击（通过收集不同解密集的偏解密份额、利用 CRT 消除 smudging 噪声），框架在**每轮重新执行 Setup、DistKeyGen、ShareReshare** 更新集体密钥材料（开销相对本地训练可忽略）。

### 2.3 协议生命周期
- 启动阶段：分布式密码学设置（Setup + DistKeyGen + ShareReshare），客户端由共享种子在本地推导初始全局权重（服务器不接触明文参数）。
- 每轮训练：服务器随机选 K 个参与者 → 客户端本地训练 → 加密上传 → 服务器同态计算 FedAvg → 广播聚合密文 → 各客户端计算部分解密份额并 P2P 交换 → 收集满 t 份后恢复全局模型。
- 解密集合既可以是静态预配置的，也可以是每轮动态指定的；解密与下一轮注册采用流水线并行以提升吞吐量。
- 提供**基线模式**（跳过全部密码步骤）用于对照实验。

## 5. 主要结果与关键发现

- **模型精度不受密码保护影响**：ThHE 模式与基线模式的训练曲线几乎完全重合（图 4）。EMNIST 上最终准确率约 88%（baseline 与 ThHE 相近），BRCA 亚型分类的 F1/macro-F1 也保持一致。这验证了 CKKS 密文域上的整数/浮点近似计算误差被控制在可忽略范围内（缩放因子 ∆=2⁴⁵），不会损害模型收敛性。
- **门限解密容错可行**：在 t-out-of-N 结构下，即使部分客户端在解密阶段掉线（只要剩余诚实客户端数 ≥ t），仍能成功恢复全局模型。论文通过 N=4/t=3 与 N=16/t=9 两组实验证明，门限参数对精度无影响，只影响通信轮次和延迟。
- **微服务隔离安全有效**：将编排器、ML Engine、Crypto Provider 彻底隔离后，在容器级别限制了攻击面；Crypto Provider 不接触网络、ML Engine 不接触密钥，既便单个容器被攻陷，敌手也无法同时获得密文与私钥份额。
- **通信开销可控**：EMNIST 下每轮通信延迟约为 12～18 秒（与训练时间相当），BRCA 下每轮通信约 2～3 秒；密文传输体积相比明文增大 10～20 倍，但由于采用 gRPC 二进制负载，仍远低于 REST/JSON 的开销。

## 6. 局限性与未来工作

- **单机部署限制**：实验仅在同一台物理机上以容器方式模拟多节点（N=4 和 N=16），未真正部署到跨地域的分布式集群。因此网络延迟、带宽瓶颈、节点异构性等真实因素未被充分评测。
- **密码学性能瓶颈**：Lattigo 的 RLWE 门限方案在批处理下虽然高效，但同态运算的扩展性仍受限于多项式阶（2¹⁴）和模数大小；当模型参数超过 1000 万级别（如 Transformer 大模型）时，密文尺寸和评估时间会急剧上升。
- **异步与动态参与**：当前协议仍是同步联邦轮次（FSM 驱动），客户端必须等待每一轮结束才能进入下一轮；虽然解密与下一轮注册有流水线，但尚未支持完全异步 FL（如 FedAsync）或客户端中途动态退出/加入的完整生命周期管理。
- **安全模型的假设较强**：论文假设聚合服务器诚实但好奇、每轮至少 t 个客户端诚实且不会相互共谋。若敌手控制超过 t 个客户端或与服务器串通，则隐私可能被破坏。此外，噪声泛洪所需的噪声量依赖对密文模数的精确设置，参数选择不当会削弱 IND-CPA-D 保证。
- **缺乏与现有框架的定量对比**：Table 1 的对比是架构层面的定性描述，没有在相同硬件/网络条件下与 Flower+单密钥 HE、FATE 等做端到端性能比较。

## 7. 综合价值评估

- **主要贡献**：MOSAIC-FL 是第一个将微服务编排、门限 CKKS 同态加密与联邦学习深度融合、并面向组学数据（TCGA BRCA）验证的框架。其 "Orchestrator / ML Engine / Crypto Provider" 三实体隔离模式比现有 FL 平台（Flower、FATE、PySyft）更细粒度地分离了职责，同时通过 gRPC 解决了 Python 与密码学库（Lattigo 的 Go/Rust 生态）之间的语言互操作难题。
- **实验质量**：数据集选择具有代表性（标准 CV 基准 EMNIST + 真实医学组学 BRCA），密码参数设置合理（128 位安全、438 位模数），时间分解和精度对比图表清晰。但缺乏跨机器真实网络环境测试，且对安全参数选择（如噪声泛洪方差、门限份额数量）的敏感性分析不足。
- **写作与可复现性**：论文结构清晰，方法描述详尽，但未提供源代码仓库链接或容器镜像，复现门槛较高；未来若能开源微服务编排配置和密码协议实现，将显著提高影响力。
- **总体结论**：MOSAIC-FL 在 "安全 FL 框架" 方向上迈出了坚实一步，尤其对医疗/基因组学的隐私保护联邦学习场景具有很强的实用性。其模块化、门限解密、每轮密钥更新等设计决策值得后续研究借鉴。若要推向生产环境，还需要补全跨节点部署、动态参与、更严谨的端到端安全基准测试等工作。
